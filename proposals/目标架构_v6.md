## 一、定位（不再摇摆）

**MolaSearch 是一个独立产品：一个独立的搜索网关（standalone search
gateway）。** `_ref/magpie` 是它的上游代码底座（fork），是"用什么造"，
不是"它是什么"。品牌、名称、数据目录、进程、文档、发布全部归
MolaSearch 所有；magpie 是被引入的上游依赖，其身份在产品里不出现。

这一定位的工程含义：

- **品牌层归 MolaSearch 所有**：窗口标题、托盘、侧栏 wordmark、设置文案、
  数据目录（`~/.config/magpie` → molasearch 自己的目录）、CLI 名、
  i18n 字符串——一次性完成品牌置换，之后这些文件是 MolaSearch 的资产，
  不再跟随上游逐字 rebase（上游对这些文件的改动按需摘取，而不是反向）。
- **上游跟踪策略**：`_ref/magpie` 记录 fork 基线 commit；上游更新按价值
  摘取（cherry-pick 安全修复与基础设施改进），MolaSearch 自己的子系统
  （searchdet/ragstore/mcpsearch/两插件页）不依赖上游的更新节奏。
- **产品边界（已定，2026-10-24）**：magpie 现有产品面**保留并做搜索化改造**，
  不是裁剪。保留清单与改造点见第三节表 B。这意味着 LLM 网关
  （127.0.0.1:3425）、agent 检测注入、provider/路由/会话/脱敏/插件市场
  全部是 MolaSearch 的组成部分——它们服务"agents 用搜索"的核心场景，
  搜索子系统与这套 agent 基础设施是同一个产品的两半。
- **文档与 README 诚实**：说"基于 magpie 代码库构建的独立搜索网关"，
  不说自己是 magpie，也不讳言来源。

## 二、架构铁律（从 magpie 学到的、v6 不再违反的）

1. **失败转移优于全局拒答**。拔掉任何一个 provider，网关失败转移到其余
   通道，判定质量可观测下降但不归零。现在的"元宝拔线 = 全局 ABSTAIN"是
   演示逻辑，v6 改为**每通道熔断器**（连败 3 次跳过 10 分钟）+ 路由失败转移。
2. **目录文案 = 引擎行为**。`modePlan` 里引擎不读的开关
   （GapRounds/NoveltyStop/Graph/AuthBoost/FreshOnly）要么实现、要么从目录
   文案里删除；`planSignature` 测试只断言引擎真实读取的开关。
3. **每个数字都是量出来的**。假配额（进程内自减的 6000）改为每通道真实
   调用账本；`hop()` 的硬编码百分比改为真实计时。
4. **判定由带权证据合成**。词袋判定（数"辟谣/官方"出现次数）升级为
   权威级 × 时效 × 矛盾对加权；中期引入小模型裁决（对齐 magpie intent
   routing 的"小模型读每一轮"模式），关键词只做预筛。
5. **一切皆插件 + conformance 门**。见基准方案场景五。

## 三、七个目标子系统（与维护者对齐的清单）

### 表 B：保留的 magpie 产品面 × 搜索化改造（2026-10-24 定）

magpie 的以下页面**全部保留**，逐页做搜索化改造；改造后它们与两个新页
（Detective、Memory & RAG）是同一个产品的连续体验，视觉令牌（子系统 7）
覆盖全壳，不再只限两个插件页。

| 保留的页面/能力 | 搜索化改造点 |
| --- | --- |
| **Agents** | 本机 agent 检测/版本/注入保留；每行增加 molasearch 接入状态（SKILL.md 与 MCP 条目是否已写入），把现在放在 Detective 页的"芯片注入"收编为 Agents 页的一键动作 |
| **会话 Sessions** | LLM 会话保留；并列"调查会话"（traceID、来源 agent、模式、判定、耗时），同一回放器渲染（统一 span schema），调查账本即子系统 4 |
| **资源库 Library（全部）** | instructions/MCP/skills/subagents 写入引擎原样保留；新增 MolaSearch 的搜索技能条目（`skills/search-modes` 等现有技能入库），写入即给 agent 装上对应搜索能力 |
| **供应商 Providers** | LLM provider 页保留；Search APIs 区扩展为完整搜索 provider 注册表（子系统 1：13 通道启停/优先级/密钥/熔断状态），嵌入模型注册表（子系统 2）同页分区 |
| **路由网关 Routing** | LLM 路由组与实时决策视图保留；搜索通道的路由复用同一页面与同一套可视化（通道组=路由组、意图路由、每通道熔断器、失败转移实时可见）——两侧共用 span 底座 |
| **脱敏 Redact** | masking 引擎与页面保留；搜索合规词表（现 `MOLA_COMPLIANCE_FILE`）收编为页面内可编辑管理，读失败 fail-closed 语义不变；查询脱敏审计并入 Sessions 明细 |
| **插件市场 Discover** | 市场机制保留；新增搜索品类：搜索通道、Store 后端、嵌入模型、网关中间件；**conformance 徽章**——通过《搜索基准测试方案.md》场景五套件的实现才可上架 |

### 表 A：七个目标子系统

| # | 子系统 | magpie 对应物 | 现状 → 目标 |
| --- | --- | --- | --- |
| 1 | **搜索 Provider 注册表** | Providers 页 + presets + providers.json | 13 通道已在同一 `Channel` 接口后（数据面已解耦）→ 注册表 UI **并入既有 Providers 页的 Search APIs 区**（表 B），不另开新页；TC3 签名降级为元宝预设的 auth 模块；密钥链已是 env→.env→providers.json |
| 2 | **嵌入模型注册表** | 模型选择器 | `embedder.go` 远程/本地双实现 + `embedderFor()` 已在 → 补预设注册；换模型必经 HotSwap（已支持重嵌入） |
| 3 | **搜索路由网关** | routing groups（smart/order/rotate/usage）+ intent routing | 最大缺口：现在每查必扇出全部通道 → 三层递进：①每模式通道组 ②意图路由（规则/小模型选通道）③会话亲和缓存 |

| 7 | **视觉令牌层** | — | molamaker 色板 + magpie 运动令牌合成 `tokens.css`；产品独立后**覆盖全壳**（保留页面在品牌置换时一并应用），新页面优先；规范见根目录《视觉样式与动画设计参考.md》 |

**统一轨迹 schema**（支撑 4/5/7 的底座）：所有管线发同一种 span
（traceID/parentID/name/start/dur/status/attrs），一套渲染器渲染一切；
与 OTel 对齐，复用 magpie `internal/otlp`。详见《搜索基准测试方案.md》§3d。

## 四、已知缺口（诊断确认的事实，修复前必须写进 as-built）

- 五个死开关：`GapRounds` `NoveltyStop` `Graph` `AuthBoost` `FreshOnly`
  在 `modePlan` 声明、被模式设置、**引擎从不读取**（M05/M07/M09/M10/M14/M19/M20
  的目录算法名没有实现）。
- 判定是关键词计数（`assess()`）：含"辟谣"即 REFUTED 方向、含"官方"即
  VERIFIED 方向，未按权威级加权。
- 元宝特权四处：全局拔线 ABSTAIN、`PrimaryEngine` 写死文案、`fusionOf`
  的 `isYuanbao`、假配额计数器。
- `hop()` 轨迹百分比为硬编码（5/15/5/70/15），与 `applyStageTiming`
  "不编造宽度"的注释矛盾。
- `Catalog()/ModeOf` 每次调用重新解析内嵌 JSON（性能小疵）。
