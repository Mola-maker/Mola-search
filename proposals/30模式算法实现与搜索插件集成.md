## 一、三层插件架构（标准化网关插件契约）

现有 13 个通道是 in-process Go（快、零依赖），社区生态是 MCP server
（npm/Go 二进制）。标准化 = 两种载体，**同一份 manifest，同一个 `Channel`
接口，同一个注册表**：

```jsonc
// plugins/search/<id>/manifest.json —— 每个搜索插件的唯一声明
{
  "id": "exa",                       // = Channel.ID()
  "name": "Exa",
  "carrier": "builtin" | "mcp",      // in-process Go 或 MCP 适配
  "mcp": {                           // carrier=mcp 时必填
    "command": "npx", "args": ["-y", "exa-mcp-server"],
    "tools": { "search": "web_search_exa" }   // 插件的哪个 tool 当搜索
  },
  "env": {                           // Providers UI 自动渲染此 schema
    "EXA_API_KEY": { "required": true, "secret": true, "label": "API Key" }
  },
  "modes": ["M02","M14","M30"],      // 模式→通道路由表（路由网关的数据源）
  "tools": [                          // 注入给 agent 的 MCP 工具（见 §四）
    { "name": "magpie_exa_find_similar", "input": { "url": "string" } }
  ],
  "conformance": ["search", "timeout", "errNoResults"]  // bench 场景五套件
}
```

- **载体 A（builtin）**：Go 实现的 `Channel`，注册进 `channels()`；适合
  协议简单、低延迟的（tavily/exa 直连 REST）。
- **载体 B（mcp）**：一个通用 `mcpChannel{spec manifest}` 适配器——把
  **任何** MCP 搜索 server 变成通道（stdio 子进程 + initialize/tools/list
  复用 `internal/mcpsearch` 的协议代码）。官方生态插件全部走这层，
  **不写一行厂商 Go 代码**。
- 注册表 = `channels()` 与 manifest 的并集；Providers › Search APIs 页按
  manifest.env 自动渲染配置表单，存 providers.json（密钥链已通）。

## 二、30 模式做实矩阵（先做实，再接插件）

现状与缺口（见 `searchdet.md` Known limitations）：引擎只读 9 个开关；
五个死开关 `GapRounds/NoveltyStop/Graph/AuthBoost/FreshOnly` 从未执行。
下表按家族给出**真实算法 + 可复用依赖**（优先 Go 标准库/成熟库，
交互型算法走 magpie 网关的小模型——即 `hyde.go` 已验证的路径）。

## 三、集成清单：现成优秀搜索插件（全部走载体 B）

| 插件 | 载体/包 | 模式适配 | 环境变量 |
| --- | --- | --- | --- |
| Exa 官方 | npm `exa-mcp-server`（v3.x，支持 Fast/Auto/Deep 三档） | /search→通用；/findSimilar→**M26 图片溯源**（同源页查找）；/answer→M03 备选 | `EXA_API_KEY` |
| Tavily 官方 | npm `tavily-mcp` | search（topic=news → **M19 盯梢**；search_depth=advanced → M02 深档）；extract → M08 雪球正文抓取 | `TAVILY_API_KEY` |
| GitHub 官方 | Go 二进制 `github/github-mcp-server`（toolsets 可裁剪到 code search） | /search/repositories→现状；/search/code+issues→**M23 代码取证**（现在只有仓库搜索） | `GITHUB_TOKEN`（PAT 5000 req/h；无 token 60/h——通道 Enabled 必须反映这个差异） |
| Brave | npm `@modelcontextprotocol/server-brave-search` | 通用 | `BRAVE_API_KEY` |
| SearXNG | npm `mcp-searxng` | 通用（自托管） | `SEARXNG_URL` |

> 注：tavily/exa 直连 REST 已是 builtin 通道（保留，低延迟）；MCP 载体接入
> 的是**直连 REST 覆盖不到的能力**（exa findSimilar、tavily extract/crawl、
> github code search）——按模式路由，不是重复接同一个搜索。

**现状修正项**：`githubChannel` 现在完全无鉴权（60 req/h 会静默耗尽）——
`Keys` 加 `GitHubToken`，env `GITHUB_TOKEN`，`Enabled` 有无 token 都真，
但 manifest 标注限速等级并在轨迹里显示。

## 四、注入插件的 tools（`tools/list` 由注册表生成）

现有 4 个工具（magpie_investigate / search_fast / debate / timeline）保留；
新工具按 manifest.tools 生成，命名 `magpie_<plugin>_<能力>`：

| 工具 | 来源 | 说明 |
| --- | --- | --- |
| `magpie_exa_find_similar` | exa MCP | 给 URL 找同源/相似页（溯源场景） |
| `magpie_tavily_extract` | tavily MCP | 给 URL 抽正文（雪球/取证） |
| `magpie_github_code_search` | github MCP | 代码/issue 检索（M23 专用） |
| `magpie_search_hybrid` | 引擎 | M02 稠密+稀疏融合检索（接 ragstore 本地库+全网） |

规则：**工具随插件启用而出现**（Provider 停用→tool 从 tools/list 消失），
conformance 未过的插件工具带 `x-mola-degraded: true` 注记。

## 五、mini 拓扑搜索逻辑动画（Modes 页每张模式卡）

每家族一个拓扑模板，SVG + 动画令牌（根目录《视觉样式与动画设计参考.md》），
静态时是模式拓扑缩略图，hover/执行时按真实轨迹点亮——**动画数据来自
`planFor()` 的结构，不是装饰**：

| 家族 | 模板 | 动画（令牌→动作） |
| --- | --- | --- |
| 直通/扩展 | 单节点→多节点扇出 | `view-in` 逐节点 stagger；通道返回时节点 `rtlive` 扩散环 |
| 图/多跳 | 菱形多跳链 | `rtflow` 蚂蚁线沿边流动；跳完成时节点 `rthit` 抖动 |
| 对抗/收敛 | 双路对撞→裁决点 | 两路反向流动，裁决点 `flash` 保持后淡出；收敛(M10)第三轮起不透明度递减 |
| 时效/权威 | 时间轴/盾牌 | `ctx-draw` 从左到右揭示；权威节点蓝点 `new-dot-ring` |
| 多模态/联邦 | 并列泳道 | 泳道独立 `rtlive`（NoFold 语义可视化）；折叠簇 `pop-out` |

实现：一个 `<svg>` 模板组件（~200 行 JS + CSS），数据 = `modePlan` 的
Queries/Hops/ProCon/GapRounds——**死开关做实后此组件自动获得真数据**。
