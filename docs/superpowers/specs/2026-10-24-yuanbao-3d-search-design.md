# 元宝真实搜索与 3D Agent 动画设计

## 目标

交付一个独立浏览器搜索页，复用元宝 SearchPro 单次搜索与多 Agent 迭代搜索能力，以真实 3D 元宝模型呈现 Agent 状态。搜索期间，不同 Agent 的元宝发生柔软挤压、黏连和堆叠。同步修复首轮验收发现的主要后端缺陷，并使用 `.env` 中已有凭证完成真实搜索回归。

## 范围

- 修复实连鉴权、HTTP 异常、参数校验、限流重试及缓存更新问题。
- 修复历史路径穿越、历史清理误删运行状态、历史保存失败处理问题。
- 修复配置文件 Profile 注入、工具启停持久化、运行时重载及冗余通知。
- 修复查询长度、覆盖率、取消传播、迭代统计及明显的去重问题。
- 新增本地 Web 服务与独立浏览器页面，不将凭证发送到浏览器。
- 新增 Three.js 元宝 Agent 场景、搜索状态动画、结果及引用展示。
- 增加后端边界、安全、真实 SearchPro 与浏览器端到端回归。

不在本次范围内：多用户账户、云端部署、搜索历史同步、复杂刚体/流体物理引擎、移动端原生应用。

## 架构

### 服务端

保留现有 MCP stdio 入口和工具契约。提取可被 MCP 与 Web 共用的搜索执行逻辑，避免两套搜索行为发生偏差。

新增本地 HTTP 服务：

- `POST /api/search`：按 `kind: "single" | "swarm"` 执行单次或多 Agent 搜索，以 NDJSON 流返回阶段、结果或错误。
- `GET /api/health`：返回服务与 dry-run 状态，不返回凭证。
- 静态文件：提供浏览器页面、官方图标及构建后的 Three.js 客户端。

服务端显式加载 `.env`，现有环境变量优先级保持为：进程环境变量、`.env`、配置文件、默认值。日志不得包含密钥。API 仅监听本机地址，校验 JSON 请求体、参数及请求大小。客户端断开时向搜索客户端与迭代引擎传播取消。

### 前端

使用 TypeScript、Three.js 和与工程一致的 ESM 构建方式。页面分为品牌区、3D 场景、搜索控制区、阶段状态区、结果及引用区。Web API 返回结构化 JSON，前端不解析 MCP 文本报告作为数据源。

### 3D 场景

每个 Agent 使用独立的 Yuanbao Agent 对象，包含：

- 放大的绿色透明玻璃球，具备折射、厚度、高光与柔和阴影。
- 中央白色面部承载腾讯元宝官方图标的配色、曲线和眨眼特征；搜索时白色区域流动变形，不使用静态平面贴图代替球体。
- 规划、检索、分析、汇总、完成、错误与取消状态具有不同表情。
- Planner、Searcher、Analyst、Synthesizer 的独立标识；辅助标识不被描述成官方图标。

动画采用可控的弹簧运动与局部形变，而非不可预测的全物理模拟。接触时压扁接触区域、增加体积补偿与短暂黏连结体；堆叠时保持稳定，完成后按阶段平滑分离。动画帧循环只更新活动对象，页面隐藏时暂停。

状态流：

1. `idle`：元宝分散并缓慢呼吸浮动。
2. `planning`：Planner 前移，子查询对应 Searcher 出现。
3. `searching`：Searcher 并行活动，元宝飞入中央，柔软碰撞、黏连并堆叠。
4. `analyzing`：Analyst 环绕元宝堆，盲区触发下一轮搜索。
5. `synthesizing`：Synthesizer 收拢结果，元宝逐渐归位。
6. `complete`：展示结果，场景保持低幅活动。
7. `error/cancelled`：停止黏性堆叠，显示对应状态并允许重试。

尊重 `prefers-reduced-motion`，关闭飞行和持续形变；WebGL 不可用时展示静态图标与完整搜索结果。

## 后端修复契约

- TC3 请求使用 `X-TC-Timestamp`；仅接受有效 HTTP 与 SearchPro 响应，异常不得缓存为空结果。
- 每次实际网络重试前重新取得限流令牌；取消能中断限流等待、在途请求与重试。
- QPS、超时、重试次数在启动时校验；Freshness 接受文档允许的无数字 `d/m/y`。
- 缓存更新已有键时不得淘汰其他键。
- 历史 ID 仅接受服务端生成格式，读取路径限制在历史目录内；清理仅针对历史文件。
- 运行状态恢复采用持久化工具集合，而不是与默认集合求并集。
- 配置 Profile 可在启动时解析并使用；未知 Profile 明确报错，不静默回退。
- `reload` 真正重载适用配置与运行状态；每次管理操作避免冗余工具列表通知。
- 派生查询满足 100 字上限；从实际返回结果提取高频新线索，过滤原查询词、虚词与重复词，不得无限追加。
- 下一轮查询必须保留原提示词核心，并包含针对方面返回结果的新线索。
- 原始研究方面贯穿所有轮次，覆盖率与最终报告不得只反映最后一轮。
- `rawHits` 表示原始命中，`newUnique` 表示当轮新增，请求计数包括已发出的失败请求。

## 错误处理

- 参数错误在本地返回明确字段信息，不发云端请求。
- SearchPro 错误保留错误码与 RequestId；前端展示可读信息，不暴露凭证或堆栈。
- 单个 Searcher 失败时保留其他成功结果，并在阶段状态中标注部分失败。
- 全部失败时返回错误状态，不生成看似成功的空报告。
- 历史写入失败时返回明确警告，不伪造可读取的历史 ID。
- 前端请求超时、取消、服务不可达和 WebGL 失败均有独立提示。

## 验收与测试

1. 运行 TypeScript 构建及现有 stdio 冒烟测试。
2. 为上述缺陷补充自动化回归，覆盖安全边界、跨重启状态、配置注入、缓存、取消、统计与 HTTP 异常。
3. 使用 `.env` 凭证执行真实单次搜索和真实多 Agent 深搜，验证鉴权、结果解析、错误处理与报告，不输出密钥。
4. 启动真实本地 Web 服务，通过浏览器完成搜索，核对网络响应、阶段推进、结果与引用。
5. 检查各 Agent 图标、3D 轮廓、黏连堆叠、完成归位、取消与失败状态。
6. 检查减少动态效果模式与 WebGL 不可用降级。
7. 最终区分自动化测试、真实云端验证和视觉检查结果；任何未完成项明确列出。

## 验收标准

- 现有 MCP 功能不回归，新增后端回归全部通过。
- 真实 SearchPro 单次与多 Agent 搜索成功，或明确记录云端侧阻塞原因。
- 浏览器可完成真实搜索并展示可点击来源。
- 各 Agent 元宝可辨识，搜索时可见挤压、黏连、堆叠和结束归位。
- 凭证仅存在于服务端，无历史路径穿越与运行状态误删。
